# 意大利语单词随身背 · 微信小程序架构设计

> 目标：把现有网页版背单词项目快速搬上微信小程序并获客。
> 现有站点：单文件 SPA，9 大篇 / 50 大类 / 439 小节 / 约 1.07 万词条；底部连播引擎、点读、闪卡/测验/拼写 + SRS；音频约 **16,750 个 mp3（≈164MB）**。

---

## 一、核心约束（决定架构的第一性原理）

| 约束 | 数值 | 对架构的影响 |
|---|---|---|
| 小程序**主包**体积 | ≤ 2MB | 音频、全量数据**都不能进包** |
| 小程序**总包**（含分包） | ≤ 20MB | 即使全进分包也装不下 164MB 音频 |
| 网络请求域名 | 必须 HTTPS + 后台白名单 | 数据源/音频需走已备案 HTTPS CDN |
| 无 DOM、双线程 | JS–Native 通信走 setData | 不能复用网页 `innerHTML` 渲染，需 WXML 数据驱动 |
| `eval`/`new Function` 受限 | 生产不可用 | 现有 `window.BOOK_DATA[N]=…` JS 数据源**必须转 JSON** |

**结论：代码做壳，数据与音频全部上 CDN。**

---

## 二、关键复用：用现有 GitHub Pages 当 CDN

你的线上站 `https://realrentao.github.io/italian-15000-words/` 本身就是 HTTPS 静态托管，已含 `audio/*.mp3` 与 `data/sec/*.js`。

- **音频**：直接复用 `https://realrentao.github.io/italian-15000-words/audio/<it|zh>/xxxx.mp3`。
- **数据**：把 `data/*.js` 转成纯 JSON（见 `tools/convert_sec.py`，已跑通），部署为 `cdn-staging/meta.json` 与 `cdn-staging/sec/<N>.json`。
- 小程序 `globalData.cdn` 指向该地址即可，**零新增后端、零新增服务器**，最快上线。

> 生产放量后建议换**腾讯云 COS + CDN**（音频走就近节点、带宽更稳、可统计），把 `cdn` 改成 COS 域名即可，代码不变。

## 三、总体架构（三层）

```
┌─────────────────────────────────────────────────────────────┐
│  表现层（小程序端，纯壳，<500KB）                              │
│  tabBar: 目录(home) · 学习(study) · 搜索(search) · 我的(mine) │
│  + section 页（点读/连播）+ player-bar 组件（全局播放条）     │
└───────────────┬───────────────────────────┬─────────────────┘
                │ wx.request(JSON)           │ InnerAudioContext(音频)
                ▼                            ▼
┌───────────────────────────┐   ┌──────────────────────────────┐
│  数据层（CDN 上的 JSON）   │   │  资源层（CDN 上的 mp3）        │
│  cdn-staging/meta.json     │   │  audio/it/*.mp3  audio/zh/*.mp3│
│  cdn-staging/sec/<N>.json  │   │  （164MB，按需流式播放）       │
└───────────────────────────┘   └──────────────────────────────┘
```

- **数据懒加载**：进哪一小节才 `wx.request` 对应 `sec/<N>.json`，存入 `globalData.secCache`，与网页 `loadParte` 一致。
- **音频流式**：点哪条播哪条；连播时用 2 个 `InnerAudioContext` 轮替，前一条 `onEnded` 触发下一条（复刻网页双 `Audio()` 引擎）。
- **状态本地化**：学习进度、SRS、设置存 `wx.setStorageSync`；跨设备同步留待「微信云开发」阶段。

## 四、分包策略

代码体量极小（全部 JS/WXML 加起来远小于 2MB），**MVP 全部放主包即可**。分包用于未来扩展：

- 主包：`app.*` + 4 个 tab 页 + `utils/*` + `player-bar` 组件 + POS 词性表。
- 分包（未来）：每门语言一本书一个分包（`package-es` / `package-fr`），新书 = 新分包，主包不变。

> 包内已用 `project.config.json` 的 `packOptions.ignore` 排除 `cdn-staging/`（JSON 不进包，只在 CDN）与 `tools/`（转换脚本）。

## 五、数据层方案

### 5.1 转换（已提供脚本 `tools/convert_sec.py`）
- 输入：`data/meta.js`（`window.BOOK_META=…`）、`data/sec/<N>.js`（`window.BOOK_DATA[N]=…`）。
- 输出：`cdn-staging/meta.json`、`cdn-staging/sec/<N>.json`（纯 JSON，emoji/重音 `ensure_ascii=False` 保真）。
- 已验证：50 个分册、10655 词条全部转换成功、字段 0 丢失（s 数组「意语句在前、中文句在后」的顺序在 JSON 中原样保留）。

### 5.2 在小程序侧
- `app.loadMeta(cb)` / `app.loadSec(gid, cb)`：带缓存的 `wx.request`，失败回调 `null`（UI 提示「加载失败」）。
- 词条数组 7 元素顺序与网页一致：`w=[中文,意语,词性,it音频,zh音频,拼音,音标,(阴性音频),(阴性词)]`；`s=[意语句,中文句,"",it音频,zh音频,拼音,"",""]`；`e` 同 `w`。

## 六、音频与连播引擎

`utils/audio.js` 实现单例顺序播放引擎（复刻网页 `P` 引擎）：

- 队列 `list`：`{src, uid, lang:'it'|'zh'}`；阴阳合写词条自动插入阳性→阴性两条 `it`。
- 播放模式：`it-zh`（意→中逐条）/ `it-only` / `zh-only`（后续补 `all-it-zh`）。
- 控制：`rate`(0.7–1.15)、`gap`(条目间隔)、`loop`、`shuffle`。
- 事件：`on(cb)` 广播进度（index/total/当前 uid），`onState(cb)` 广播播放态——`player-bar` 与 `section`/`study` 页同时订阅，实现进度条 + 当前条高亮。
- 点读：`wx.createInnerAudioContext()` 每次新建即播（保证从头播放，避免缓存对象 ended 后二次点击无声，同网页 `say`）。

## 八、学习模式与 SRS（获客/留存的重心）

- **闪卡**：正面意语词 + IPA 音标 + 🔊 发音；点击/按钮翻面看中文 + 拼音；「认识 / 不认识」按钮。
- **测验**：中文释义四选一选意语，答错标红、答对标注，自动朗读。
- **拼写**（后续）：中文 → 输入意语 → 校对（重音归一 `perche≡perché`）。
- **SRS**：5 档间隔（10 分 / 1 时 / 1 天 / 3 天 / 7 天），「不认识」清零、「认识」进档；`mine` 页显示到期数，驱动每日回访（留存）。

## 十一、风险与注意

1. **GitHub Pages 音频带宽**：个人站免费额度有限，放量后audio 偶发卡顿 → 尽早切 COS+CDN（代码仅改 `cdn` 常量）。
2. **搜索全量加载**：当前客户端加载 50 个分册再过滤，数据量小可接受；量大时改服务端搜索或预建索引 JSON。
3. **音频自动播放限制**：微信禁止无交互自动播放，连播必须由用户点「播放」触发（已遵守）。
4. **类目与类目资质**：教育类小程序通常无需特殊资质，但「付费会员」上线前需确认微信开放类目要求。
5. **数据保真**：转换已逐字段校验，s 数组顺序、阴性形态音频(第 8 元素)均保留；改数据时务必按既有 7/9 元素顺序，避免损坏。

## 十三、微信云开发：进度多端同步（代码已就绪）

代码层已完整实现，并按「无云环境自动降级本地」设计——**不配云也能正常用（本地存储），配了云即自动多端同步**，不会因缺少云环境而崩溃。

**已落地文件**
- `app.js`：`onLaunch` 调 `wx.cloud.init()`；`markDone / srsUpdate / saveSettings` 变更后自动 `_syncCloud()`；登录后 `_mergeCloud()` 把云进度合并回本地。
- `utils/cloud.js`：云初始化、取 OPENID、进度读写封装（全量覆盖式存 `progress` 集合，docId=openid）。
- `cloudfunctions/getOpenid/`：云函数返回调用者 OPENID（小程序端无法直接取）。

**启用 5 步**
1. 微信公众平台 → 开通「云开发」→ 新建环境，复制**环境 ID**。
2. 把 `utils/cloud.js` 顶部 `const ENV = 'your-cloud-env-id'` 改成你的环境 ID。
3. 云开发控制台 → 数据库 → 新建集合 `progress`，权限设为「仅创建者可读写」。
4. 右键 `cloudfunctions/getOpenid` → 上传并部署（云端安装依赖）。
5. `project.config.json` 的 `appid` 改为你自己的小程序 AppID。

**同步语义**：`done`（已学完标记）取并集；`srs`（复习队列）取到期时间较新者；`settings`（语速/显隐）以云覆盖。首次登录若本地已有进度，会以「合并后更全」的结果落库，不丢数据。
